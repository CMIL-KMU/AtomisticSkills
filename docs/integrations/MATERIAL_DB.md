# Optional Anvil material DB contracts

The historical provider still owns all 31 supplied-data functions. Active Anvil
integration is now governed by the installed atomistic_analysis.catalog module
and packaged capabilities.json: exactly 27 explicit operations, excluding the
four drug-derived operations and the 20 drug/docking tutorial entries. This is
Anvil admission policy, not removal of scientific source functions or old data.
Adding a provider schema alone does not enable an operation in Anvil.

Catalog listing exposes source tutorial scope, prerequisites/guidance, input
schemas, admitted DB ports, typed publication mappings, enablement and local
dependency metadata. Metadata presence is not a successful execution certificate.
Server and worker both validate the same content-addressed material-request/v2
contract. Existing inline v1 contracts and reports remain unchanged.

Anvil owns DB resolution, requester/project authorization, scientific snapshots,
Calc/Method, Result/Target/Source/Link and transactional publication. Recipes stays
a thin native worker adapter; scientific methods stay here. The companion Anvil
packages/anvil-db/anvil_mcp/db/MATERIAL_SKILLS.md contains executable construction,
all operation mappings, display details and rollout prerequisites. No tutorials
are converted into unbounded module/URL/shell dispatch.

The current qualification uses installed wheels and disposable PostgreSQL for
registered structure → XRD → typed Result → browser, structure lineage,
stored MD → RDF/density, multi-input hull/EOS/scalars, every publication mapping,
permissions/replay/revision/hash/contract denials and atomic rollback.
Independent provider reference tests are copied without the source-tree conftest
into the isolated evidence directory so installed imports are actually exercised.
Drug source functions are preserved but not dispatched by the Anvil qualification.

To extend: explicitly admit the operation, preserve one scientific implementation,
define versioned input/output/target contracts, map to existing typed models,
test independent numerical references and negative cases, then qualify native
installed request/build/execute/collect/read paths. Update immutable consumer pins.
Unsupported engines, checkpoints and full workflows remain declared prerequisites.
